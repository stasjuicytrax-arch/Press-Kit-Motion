# ТЗ: лендинг Press Kit Motion

Версия 1.0 · 2026-10-20 · заменяет мини-ТЗ `TZ-landing.md` (оставлен для истории).

Читать вместе с:
- `PRODUCT.md` — продукт, аудитория, ограничения (формат Impeccable).
- `DESIGN.md` — дизайн-система, единственный источник стилей.

## 1. Что делаем

Одностраничный продающий сайт услуги «анимированный сайт-пресс-кит для диджея и артиста». Человек приходит из ВК Рекламы или поста в Телеграм-канале, смотрит живые сайты артистов, примеряет пресс-кит на своё имя и пишет в Телеграм **@stasjuicytrax**.

Единственное целевое действие: клик по кнопке «Написать в Телеграм». Всё остальное на странице подводит к нему.

Впечатление: ультрасовременно, светло, много воздуха, технологично, 3D, жидкое стекло, вау с первого экрана.

## 2. Аудитория и трафик

- Русскоязычные диджеи, электронщики, вокалисты, ведущие; промоутеры как вторичная аудитория.
- Трафик в основном с телефонов. Вёрстка mobile-first: 360–430px, потом 768, 1024, 1440.
- Язык русский. Тексты лежат в `src/content/ru.ts`, чтобы позже добавить `en.ts` и маршрут `/en/` без переделки компонентов.

## 6. Ассеты

### 6.1 Записи сайтов артистов (главный визуал)

Создать `scripts/record-sites.mjs` (Playwright + ffmpeg). Для каждого сайта:

| Ключ | URL | Подпись |
|---|---|---|
| nagoo | https://djnagoo.site | DJ Nagoo · Санкт-Петербург |
| lolly | https://djlolly.site/ | Lolly · Янгон · Bass, DnB |
| kingdom | https://stasjuicytrax-arch.github.io/39Kingdom/ | 39 Kingdom · дуэт · melodic techno |
| sunrise | https://stasjuicytrax-arch.github.io/djsunrise/ | Sunrise · Бангкок, Паттайя |
| toropov | https://stastoropov-site.vercel.app/ | Стас Торопов · Пермь · ведущий |
| oppaacha | https://oppaacha.site/ | OPPAACHA · продюсер и DJ, Become Human Records |

Подписи сверить с самими сайтами при записи.

Что записать:
1. **Мобильная запись** 390×844, плавный автоскролл первых 3–4 экранов, 10–12 секунд.
2. **Десктопная запись** 1440×900, автоскролл, 10–12 секунд.
3. **Постеры**: первый кадр каждой записи, AVIF + JPG.
4. **Кропы блоков** для карусели «Что внутри»: первый экран, цифры, видео, галерея, букинг (скриншоты элементов по селекторам или по координатам).

**Качество (версия 2, 2026-10-21).** Первые записи вышли в мыле и квадратах: 720px при 1.5 МБ на 11 секунд это около 1 Мбит/с, а у сайтов артистов градиенты и мелкий текст, кодек их разваливает. Плюс встроенная запись Playwright (`recordVideo`) сама по себе пишет низкое качество. Новые правила:

1. **Не использовать `recordVideo`.** Снимать кадры: Playwright с `deviceScaleFactor: 2`, скролл детерминированный (`window.scrollTo` на каждый кадр по easing-кривой), `page.screenshot({type:'png'})` на каждый кадр, 30 кадров/с. Перед записью дождаться загрузки шрифтов, картинок и окончания анимаций первого экрана (2–3 с), отключить курсор.
2. **Разрешение:** телефон 390×844 CSS при DPR 2 → кадр 780×1688, итоговое видео 780 по ширине (или 1080, если исходник сайта это держит). Десктоп 1440×900 при DPR 1.5 → 2160×1350, итоговое видео 1920 по ширине.
3. **Кодирование из PNG-кадров:**
   - MP4: `ffmpeg -framerate 30 -i f_%04d.png -c:v libx264 -preset slow -crf 18 -tune animation -pix_fmt yuv420p -movflags +faststart -an mobile.mp4`
   - WebM: `ffmpeg -framerate 30 -i f_%04d.png -c:v libvpx-vp9 -crf 30 -b:v 0 -row-mt 1 -deadline good -cpu-used 2 -pix_fmt yuv420p -an mobile.webm` (двухпроходный, если время есть)
   - В `<video>` первым `<source>` ставить MP4 (H.264), вторым WebM: на iPhone так стабильнее.
4. **Бюджет веса:** телефон до 4 МБ, десктоп до 6 МБ на ролик. Ролики грузятся лениво (`preload="none"`, старт по IntersectionObserver), поэтому вес не влияет на первый экран. Если не влезает, сначала укоротить ролик до 8 секунд, потом поднять CRF на 2. Разрешение не снижать.
5. **Постеры:** первый кадр в AVIF (качество 60) и JPG (качество 85), в том же разрешении.
6. **Проверка:** открыть `/preview/` на iPhone и на мониторе, увеличить кадр с мелким текстом и градиентом. Квадратов и «лесенок» быть не должно.

Класть в `public/media/sites/<key>/`. Большие файлы через Git LFS, если репозиторий начнёт пухнуть (GitHub Pages отдаёт LFS-файлы только как указатели, поэтому для LFS деплоить на Vercel).

### 7.1 Первый экран (Hero) — «Стеклянная капля»

**Утверждение:** это анимированные сайты-пресс-киты для артистов, и вот они живые.

**Версия 3 (2026-10-21), «Стеклянная капля».** Решение владельца после просмотра v1:
- надпись поверх пёстрых экранов не читалась (`mix-blend-mode: difference` над видео даёт кашу);
- не было вау-эффекта;
- **кейсы на первом экране не нужны**: сайты артистов показываются только в секции «Работы» (7.3) и ниже.

Правило: надпись всегда сплошная `--ink` на чистом фоне `--bg`; поверх неё может проходить только стекло, и только частично.

**Идея:** огромное «Press Kit Motion», над которым живёт капля жидкого стекла. Капля тянется за курсором, преломляет и увеличивает буквы под собой, как линза, с радужной кромкой. Это одновременно «вау», жидкое стекло из брифа и намёк на «Motion»: надпись оживает под каплей.

**Композиция, десктоп (100svh):**
- **Монумент** в центре экрана в две строки: «Press Kit» / «Motion», размер ~17vw, вес 600, трекинг −0.06em, интерлиньяж 0.82, `--ink`. Занимает почти всю ширину между полями. Рендерится **внутри WebGL** через drei `<Text>` (troika) тем же файлом Onest, чтобы стекло могло его преломлять. Для SEO и скринридеров рядом обычный `h1` (визуально скрыт, когда сцена активна; виден как обычный текст, если WebGL нет).
- **Капля (Three.js).** Сфера высокой детализации (icosahedron, detail 48–64), форма «дышит»: вершины смещаются simplex-шумом в вершинном шейдере (амплитуда 0.06–0.12, медленно), при быстром движении курсора капля вытягивается по направлению движения (растяжение по скорости, пружина). Материал `MeshTransmissionMaterial` (drei): `transmission 1`, `thickness 1.2`, `ior 1.25`, `roughness 0.04`, `chromaticAberration 0.06`, `anisotropicBlur 0.1`, `distortion 0.25`, `distortionScale 0.4`, `temporalDistortion 0.12`, `backside true`, лёгкий оттенок `#F2F2EE`. Освещение: `<Environment>` из нескольких `Lightformer` (белые полосы-софтбоксы + одна лаймовая `--glow-1` сбоку) для бликов на стекле. Размер капли около 26% ширины окна.
- **Текст под монументом**, на чистом фоне. Слева внизу: подзаголовок `--step-lead` (до 30ch, 2–3 строки) и факты. Справа внизу: главная CTA «Написать в Телеграм» (Liquid Glass Button, магнитная) и под ней ссылка «Смотреть работы ↓».
- Больше ничего на первом экране нет: ни экранов, ни карточек, ни бейджей.

**Движение («вау»):**
1. **Падение, 0–1.6с.** Надпись уже видна. Сверху падает капля, ударяется о слово «Kit», расплющивается и расходится волной (кольцевое искажение по буквам 400ms), затем собирается обратно в каплю с пружинным «дрожанием». Один раз за визит (`sessionStorage`).
2. **Курсор.** Капля следует за курсором с запаздыванием (пружина: stiffness ~90, damping ~14), над буквами чуть увеличивается. Клик или тап по сцене даёт «всплеск»: короткая рябь по капле и буквам рядом.
3. **Без курсора и на телефоне.** Капля сама медленно плавает по траектории-восьмёрке над надписью; после первого касания экрана следует за пальцем; наклон телефона сдвигает её (DeviceOrientation только после жеста пользователя).
4. **Скролл (v3.1, 2026-10-21).** Капля живёт только на первом экране и в угол не переезжает. На первых 60vh скролла она улетает вверх-вправо, уменьшается и гаснет (`exit²`), после этого Canvas останавливается (`frameloop="demand"`), не перекрывает контент и не ловит клики. Пока первый экран виден, капля медленно плавает по всей надписи, курсор лишь мягко притягивает её (не больше 0.6 радиуса) и не «приклеивает».
5. **Reduced motion:** капля стоит неподвижно над «Kit», без падения и без следования за курсором. Без WebGL: статичный кадр капли поверх надписи (AVIF, отрисованный заранее) и обычный DOM-текст.

**Телефон:** монумент в три строки «Press» / «Kit» / «Motion» по ~27vw, занимает верхние 60% экрана, капля ~42% ширины. Подзаголовок 18px и кнопка на всю ширину ниже. Разрешение передачи (`resolution`) 256, `samples` 3, DPR до 1.5.

**Производительность:** `MeshTransmissionMaterial` дорогой. Десктоп: `resolution 512`, `samples 6`. Слабое устройство (см. `DESIGN.md` §9) → статичный кадр. Canvas грузится лениво после первого рендера DOM, h1 и подзаголовок видны сразу.

**Референс-компонент:** liquid-sculpture-hero (21st.dev, @gughigug) из списка владельца — для идеи реакции на курсор; его частицы не копируем, у нас стеклянная капля.

**Тексты:**
- `h1` (визуально монумент + подзаголовок, семантически одна фраза): «Press Kit Motion — анимированные сайты-пресс-киты для диджеев и артистов». Бегущие копии `aria-hidden`.
- Подзаголовок: «Анимированный сайт вместо PDF. Промоутер открывает одну ссылку и сразу видит, как ты звучишь и выглядишь.»
- Факты: «От $100 · готово за 5–10 дней».
- CTA: «Написать в Телеграм».
- География: «Сайты для артистов из Петербурга, Перми, Бангкока и Янгона».

### 7.2 Проблема — «Заголовок как подпись к панораме»

**Утверждение:** PDF и набор ссылок проигрывают живому сайту.

**Композиция:** секция 100svh. В верхней трети заголовок `--step-head` по левому полю, под ним две короткие подписи рядом (по 2 строки, размер `--step-body`, ширина 260px каждая). Через 40px начинается панорама на всю ширину: горизонтальная лента из десктопных записей всех сайтов подряд, видна верхняя часть, остальное доезжает при скролле. Лента сдвигается влево по мере скролла (scroll-linked, transform).

**Телефон:** заголовок 12vw, подписи в один абзац, панорама 4:5 из мобильных записей.

**Тексты:**
- `h2`: «Промоутер не листает PDF»
- Подпись 1: «Он открывает твою ссылку в Телеграме между делами. У тебя секунд десять.»
- Подпись 2: «За эти десять секунд сайт показывает видео с твоих сетов, цифры и кнопку букинга.»

### 7.3 Работы — «Большие имена, липкое превью»

**Утверждение:** это уже сделано для реальных артистов, и всё можно открыть.

**Версия 2 (2026-10-21), «Шоурум» — действующая.** Десктоп: секция в один экран. Сверху переключатель из 5 имён, у активного лаймовая полоса прогресса до автосмены (8 с, пауза при наведении, стрелки клавиатуры). По центру сцена: окно браузера 16:10 с десктопной записью и телефон 9:16 с мобильной записью поверх правого нижнего угла; ничего не обрезается. Слева у низа сцены: имя, «город · жанр · на сцене с YYYY» (год только там, где он известен: Nagoo 2005, Lolly 2015), стеклянная кнопка «Открыть сайт». ## 8. Телеграм, UTM и аналитика

- Хелпер `src/lib/telegram.ts`: собирает ссылку `https://t.me/stasjuicytrax?text=...`.
- Текст по умолчанию: «Привет! Хочу сайт-пресс-кит.» + место клика (пакет, имя из конструктора) + источник.
- Источник: читаем `utm_source` из URL при входе, сохраняем в `sessionStorage` (в try/catch). `vk` → «Я из ВК», `telegram`/`tg` → «Я из Телеграма», иначе ничего.
- UTM-параметры не ломают страницу и не исчезают при навигации по якорям.
- **Проверить на реальных телефонах**, что `?text=` подставляется в чат с пользователем (iOS Telegram, Android Telegram, Telegram Desktop). Если клиент игнорирует текст, кнопка всё равно открывает чат.
- Яндекс Метрика: счётчик из `VITE_YM_ID`, webvisor по желанию владельца. Цели: `tg_click` (параметр `place`: hero, nav, sticky, builder, price, cta, footer), `portfolio_open`, `builder_used`.

## 10. Производительность

- Первый экран показывает текст сразу; Three.js-чанк и видео грузятся после.
- LCP < 2.5с на мобильном 4G (Lighthouse mobile), CLS < 0.05, INP < 200мс.
- Видео: `preload="none"`, `muted`, `playsinline`, `loop`, запуск через IntersectionObserver, пауза вне экрана.
- Картинки AVIF/WebP с `width`/`height`, `loading="lazy"` везде кроме первого экрана.
- Шрифт: preload кириллического подмножества Onest.
- Слабое устройство или `Save-Data` → без WebGL, без автозапуска видео (постеры + кнопка Play).
- `backdrop-filter` только на фиксированных и небольших элементах (кнопки, навигация, телефон), не на больших прокручиваемых областях.

- Контраст текста 4.5:1, крупного 3:1, включая текст на стекле.
- Бегущие копии строки и декоративный Canvas: `aria-hidden="true"`.
